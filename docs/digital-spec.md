# 《冒險者公會》線上版功能規格

> 版本：v0.1（第一版範圍）
> 遊戲規則見 `docs/spec.md`，本文件只描述線上版的功能。

---

## 1. 第一版範圍

| 項目 | 決定 |
|---|---|
| 對局人數 | 4 人 |
| 帳號 | 不需要 |
| 開局方式 | 建立房間、分享連結 |
| 平台 | 網頁優先（桌面瀏覽器），手機可以打開但不針對小螢幕設計 |
| 時間限制 | 不設 |
| 介面語言 | 繁體中文 |

**第一版不做**：帳號、戰績、AI 對手、觀戰、手機版介面、速開版。

---

## 2. 房間

| 項目 | 規格 |
|---|---|
| 建立 | 房主建立房間，取得房間連結和房間碼 |
| 設定 | 房主設定榮譽模式（王國評選／王國指派／王國競爭）、是否加入史詩任務、王國榮譽卡的抽卡方式（依路線平均／完全隨機）、勾選最多 2 個擴充系列（不勾選即為預設模式），以及擴充模式下是否「只從基礎版補滿」 |
| 加入 | 打開連結或輸入房間碼，輸入暱稱後入座 |
| 開始 | 4 個座位都坐滿後，由房主開始遊戲 |
| 關閉 | 連續 **7 天**沒有活動後自動關閉。所以房間狀態必須存進資料庫，伺服器重啟也不會遺失 |

---

## 3. 斷線重連

| 情況 | 處理 |
|---|---|
| 同一個瀏覽器重新打開 | 瀏覽器記住座位，打開連結就自動回到原本的座位 |
| 換裝置或清除瀏覽器資料 | 輸入房間碼後，畫面列出目前斷線中的座位，選擇自己的座位回到遊戲 |

說明：第二種方式理論上可以冒充其他玩家。第一版是朋友之間開房，接受這個風險。

---

## 4. 遊戲進行

| 項目 | 規格 |
|---|---|
| 規則判定 | 所有規則判定和擲骰都在伺服器處理，玩家無法作弊 |
| 隱藏資訊 | 只傳給有權看的玩家，例如王國指派模式的榮譽卡、牌庫的順序 |
| 等待他人選擇 | 效果要求其他玩家做選擇時（例如布魯斯、里諾），整局暫停等待那位玩家 |
| 遊戲紀錄 | 顯示每一步誰做了什麼、擲出幾點 |

### 4.1 反悔

**原則：只要還沒有揭露新的資訊，就可以反悔。**

| 可以反悔 | 不能反悔 |
|---|---|
| 選錯冒險者、選錯任務、還沒確認的選擇 | 擲骰之後 |
| | 翻開牌庫的牌之後 |
| | 其他玩家已經依此做出選擇之後 |

連帶的影響：
- 沒有替換成員的招募會讓酒館從牌庫補一張新的冒險者，屬於「翻開牌庫」，所以**不能反悔**。
- 替換成員的招募不會翻開牌庫（被解僱的冒險者直接放進空位），所以**可以反悔**。
- 介面在執行「不能反悔」的操作之前，會提醒玩家確認。

### 4.2 卡住時的處理

不設時間限制。有玩家長時間沒有動作時：

| 版本 | 處理 |
|---|---|
| 測試版 | 房主可以替該玩家**跳過目前的回合**或選擇 |
| 正式版 | 之後再決定 |

## 5. 測試模式

**放入第一版**：一個人在同一個畫面操作 4 個公會，用來測試規則與平衡。

## 6. 技術架構

| 項目 | 決定 |
|---|---|
| 語言 | 全部使用 **TypeScript**，前端、伺服器、規則引擎共用同一套規則程式 |
| 規則引擎 | **自行開發**，不使用現成桌遊框架 |
| 連線 | WebSocket（例如 Socket.IO） |
| 前端 | React |
| 資料庫 | 🟡 暫定：SQLite |
| 主機 | 開發時再比較各平台方案 |
| 開發 | 由 Claude 開發，設計者負責測試與確認 |

### 6.1 專案結構

| 部分 | 內容 |
|---|---|
| `engine` | 規則引擎。純邏輯，不碰網路和資料庫 |
| `server` | 房間、連線、存檔，把玩家操作交給引擎判定 |
| `web` | React 遊戲畫面 |
| `data` | 從試算表匯出卡片資料的腳本，以及產出的 JSON |

### 6.2 規則引擎設計重點

| 重點 | 說明 |
|---|---|
| 固定種子的亂數 | 同樣的種子和操作必定得到同樣結果，可以重播整局、重現錯誤 |
| 等待決策 | 需要某位玩家選擇時，引擎暫停並記錄「正在等誰、要選什麼」 |
| 檢查點式反悔 | 每次揭露新資訊（擲骰、翻牌、他人做出選擇）就建立檢查點，只能反悔到最近的檢查點 |
| 技能模板 | 試算表的「技能框架」對應到程式模板；學舌鳥、菲特等獨特技能另外實作 |
| 事件紀錄 | 所有操作與結果都記錄下來，作為遊戲紀錄、存檔與重播的依據 |

### 6.3 卡片資料流程

試算表是正本。腳本從試算表匯出、檢查格式後產生 JSON，存進存放庫。試算表更新後重新執行腳本即可。

## 7. 內容更新

**定期加入新卡片（任務、角色），並隨時維護卡片數值，是本遊戲最大的特色之一。** 架構以「卡片是資料、程式只負責機制」為原則。

### 7.1 分工原則

| 誰 | 負責 |
|---|---|
| 設計者 | 在 Google 試算表用**自然語言**撰寫卡片文字，填寫數值欄位（基礎骰數、薪資、任務獎勵等）與實裝狀態 |
| Claude | 把卡片文字轉換成程式格式、檢查、開發新機制、模擬測試、發布 |

試算表是卡片的**唯一正本**。設計者不需要維護模板代碼或參數欄位。

### 7.2 技能子句對照表

- 每個技能拆成子句，每個子句對應一個技能模板（見 `docs/skill-templates.md`）。
- 對照表（`data/skill-mapping.csv`）放在 GitHub 存放庫，**由 Claude 維護**，不放進試算表。
- **自動抓取參數**：每個模板都有標準句型，例如「當此冒險者參與{X}任務時，任務難度調整{Y}」。匯入腳本用卡片文字比對標準句型，自動抓出參數。只改數字時，不需要人工處理。
- **比對不上時**：句型改變或出現新機制，腳本會在檢查報告中標出，由 Claude 判斷沿用現有模板或開發新模板。

**撰寫建議**：盡量沿用現有句型，例如難度一律寫「任務難度調整 X」。句型一致，大部分修改都能自動處理。

### 7.3 實裝狀態

試算表的冒險者、衍生物、道具、任務分頁各有一欄**實裝狀態**：

| 值 | 匯入遊戲時 |
|---|---|
| 實裝 | 匯入正式卡池 |
| 測試 | 只在測試模式出現，用於新卡試玩 |
| 未實裝 | 略過，可以放構想中或資料不完整的卡片 |

### 7.4 卡片版本

| 規則 | 說明 |
|---|---|
| 版本號與更新紀錄 | 每次發布產生新版本，附上「改了哪些卡、改了什麼」 |
| 對局鎖定版本 | 房間使用**開局時**的卡片版本，進行中的對局不受更新影響；新開的房間才使用新版本 |
| 擴充系列 | 卡片分為基礎版與擴充系列。房主開房時可以勾選最多 2 個擴充系列（見規格書第 17 節） |

### 7.5 更新流程

更新頻率約 **1–2 個月一次**，採用人工觸發、**經過檢查後再發布**的流程：

| 步驟 | 負責 | 內容 |
|---|---|---|
| 1 | 設計者 | 修改或新增試算表中的卡片 |
| 2 | 設計者 | 開一個 Claude 工作階段，告知「卡片有更新」 |
| 3 | Claude | 讀取試算表，產生檢查報告與差異清單 |
| 4 | Claude | 需要時開發新模板，並跑模擬對局 |
| 5 | 設計者 | 看報告，在測試模式試玩 |
| 6 | 設計者 | 確認後通知 Claude 發布；新開的房間開始使用新版本 |

### 7.6 不同情況的處理

| 情況 | 設計者 | Claude | 需要寫程式 |
|---|---|---|---|
| **調整數值**（例如薪資 2→3、難度調整 1→2、獎勵 3→4） | 直接改試算表 | 自動抓出新數值，列入差異清單 | 否 |
| **新卡，使用現有句型** | 新增一列，實裝狀態填「測試」；試玩滿意後改為「實裝」 | 自動對應現有模板，跑模擬 | 否 |
| **新卡，有全新機制** | 照平常語氣撰寫 | 標出無法對應的技能；文字有歧義時先詢問設計者；開發新模板與測試 | 是（之後同類卡片不再需要） |
| **下架或暫停卡片** | 實裝狀態改為「未實裝」 | 發布 | 否 |

小幅數值調整可以只看差異清單就發布，不一定要試玩。

### 7.7 檢查報告

每次更新都會產生一份報告，內容包括：

| 區塊 | 內容 |
|---|---|
| 修改 | 哪些卡改了哪些數值或文字，例如「凱菲：薪資 2 → 3」 |
| 新增 | 新卡是否全部對應現有模板；無法對應的技能 |
| 刪除／下架 | 移除或改為未實裝的卡片 |
| 問題 | 格式錯誤、引用不存在的標籤或卡名、規則歧義 |
| 模擬 | 更新前後的平衡變化，例如各公會勝率、卡片使用率 |

範例：

```
卡片更新報告：v1.3 → v1.4

修改（3）
  凱菲            薪資 2 → 3
  萊昂【風險評估】  難度調整 1 → 2
  清除史萊姆        獎勵 3 金 → 4 金

新增（2）
  沙漠嚮導 阿里     ✅ 全部對應現有模板
  時空旅人 X        ⚠️ 【交換命運】對不上任何模板，需要開發

問題（1）
  沙漠嚮導 阿里     ⚠️ 引用標籤 [沙漠]，但沒有任務帶這個標籤

模擬（1000 局）
  加入新卡後，各公會勝率差異 < 2%
```

進行中的對局不受更新影響，繼續使用開局時的版本（見 7.4）。

## 8. 卡片呈現

參考魔法風雲會線上版的呈現方式。

### 8.1 原則

| 原則 | 說明 |
|---|---|
| 文字逐字照抄試算表 | 卡名、類型、技能、風味文字都直接使用試算表的原文，保留換行。試算表改了，卡片就跟著改 |
| 插畫與排版分離 | 圖片只放**插畫**；卡框、文字、數值由網頁即時排版。調整數值時不需要重做圖片 |
| 文字與規則一致 | 畫面顯示原文，規則引擎使用子句對照表；匯入檢查確保兩者一致（見 7.2） |

### 8.2 卡面內容

| 位置 | 內容 | 來源 |
|---|---|---|
| 卡名 | 例如「蛇眼」布萊克 | 試算表 |
| 插畫 | 角色或任務的圖 | 插畫檔 |
| 類型列 | 種族．職業．特質 | 試算表 |
| 數值 | 基礎骰數、薪資（任務卡：時限、條件、獎勵） | 試算表 |
| 技能 | 完整技能文字 | 試算表，逐字照抄 |
| 風味文字 | 斜體 | 試算表 |
| 遊戲狀態 | 橫置（卡片轉 90 度）、指示物數量 | 遊戲中即時顯示 |

### 8.3 互動

| 功能 | 說明 |
|---|---|
| 放大 | 滑鼠移到卡片上即放大顯示 |
| 關鍵字說明 | 滑鼠移到【集結】、橫置、[潛行] 等詞上，顯示規則說明；說明文字來自規格書術語表 |
| 詳細頁 | 點開卡片顯示故事背景、英文名稱 |
| 雙面卡 | 可以翻面查看背面 |

### 8.4 插畫

| 項目 | 狀態 |
|---|---|
| 來源 | 已有插畫（AI 繪製），存放在設計者的 Google 雲端硬碟 |
| 檔名 | 🔴 待調整：改為卡片編號，例如 `STD-C02.png`，背面為 `STD-C02B.png` |
| 比例 | 🔴 待決定，之後再調整 |
| 缺圖時 | 顯示預設背景圖 |

## 9. 開發里程碑

| 階段 | 內容 | 完成後可以做什麼 |
|---|---|---|
| M0 專案骨架 | 建立專案結構、自動測試 | — |
| M1 卡片資料管線 | 試算表匯入、依標準句型自動抓取參數、格式檢查、差異清單、檢查報告、卡片版本 | 每次改完試算表，自動產生檢查報告與差異清單 |
| M2 核心規則 | 回合與階段、公會行動、招募與解僱、任務與時限、派遣與擲骰、薪資、輪末結算、市場輪替、王國榮譽計分。先不含卡片能力 | 用「沒有能力的卡片」跑完整局 |
| M3 效果系統 | 觸發、替代、指定、等待決策；依技能模板實作卡片能力，再實作獨特技能 | 所有卡片能力都能運作 |
| M4 測試模式 | 網頁介面，一個人操作 4 個公會，不需要伺服器 | **設計者開始實際試玩、調整平衡** |
| M5 線上對戰 | 伺服器、房間、斷線重連、存檔、隱藏資訊、反悔 | 4 人線上對戰 |
| M6 部署 | 選擇主機、上線 | 分享連結給朋友試玩 |

測試模式（M4）排在線上對戰（M5）之前，讓設計者能最早開始試玩。

### 9.1 開發前需要的資料

| 項目 | 狀態 |
|---|---|
| 任務卡的數值（條件、時限、獎勵） | 22 張中只有少數填了數值，M2 之前需要補齊，或先用暫定數值 |
| 王國榮譽卡 | 分頁是空的，M2 之前至少需要排名型的卡片清單 |
